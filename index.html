About

I work at the intersection of economics, data, and engineering — building reproducible R / Python pipelines, validation and QA workflows, and AI-assisted documentation tooling that turn macro and financial data into versioned, reviewable artifacts.

My core work is production-style analytics: validating and stress-testing models, building reproducible data pipelines, producing forecasts with documented uncertainty, and using AI coding tools responsibly to make recurring QA, review, and documentation more systematic — packaged so a reviewer can audit every step from Git.

I also work on experimentation and metrics analysis — designing and evaluating A/B tests (North Star metrics, power / MDE, CUPED variance reduction, guardrails) and translating results into clear launch and monitoring recommendations. The validation mindset I bring to risk models — does this number actually measure what it claims? — carries directly into product metrics and AI-workflow evaluation.

A reproducible study of LLM-based QA agents on synthetic model-monitoring anomaly review: 15 labelled scenario types, transparent feature engineering and a deterministic rule baseline, a schema-constrained agent with retry / validation, an optional second-pass reviewer agent, four prompt conditions, and an evaluation suite spanning precision / recall, confidence calibration (ECE, Brier), unsupported-claim analysis, and paired statistical testing (McNemar, paired permutation, Benjamini–Hochberg). How I use AI tools

I treat AI coding tools as collaborators on boilerplate, refactoring, and documentation — not as substitutes for analyst judgment. Every repo that uses an LLM in its workflow includes a CLAUDE.md defining how the model should behave, a clear human-review step before outputs are shared, and explicit limitations of what the AI-assisted output represents.
